# 顶栏取舍：6 个控件 → 标题 + 规格胶囊 + 更多

- 日期：2026-11-12
- 证据：`design-demos/header-study.html` · 截图 `design-demos/shots/header-study.png`（390pt，三版同屏）

## 三版实测

| 版本 | 形态 | 读起来的问题 |
|---|---|---|
| V1 现状 | 返回 / 居中歌名·歌手 / 4 个图标（倍速、定时、音效、设置） | 4 个图标靠猜；标题被左右各 3 个 44pt 命中区挤成窄条，中文歌名稍长就截断 |
| V2 | 返回 / 居中歌名·歌手 / 「FLAC ⌄」规格胶囊 / 「…」 | 顶栏只剩 2 个命中区；规格用文字，看得懂；倍速/定时/音效/设置进「…」 |
| V3 | 返回 / 左对齐歌名·歌手·专辑 / 规格 + 「…」 | 和 A 版「标题靠左、读数靠右」同一网格；但导航栏左对齐标题偏离 iOS 习惯 |

## 结论：采用 V2

理由：
1. **iOS 导航栏的标题是居中的**（HIG navigation bars）。V3 的左对齐适合内容区，不适合顶栏；A 版原型顶部也是“居中状态 + 右侧更多”。
2. **规格写在顶栏比藏进弹层有用**：用户切歌时最想知道“这首是不是无损”，这是每首歌都会变的信息；倍速/定时/音效/设置是设置项，进「…」不损失日常效率。
3. V1 的 4 个图标里，`+`（倍速？）、方块（定时？）这类符号本身就没有公共语义，读屏器之外的人只能试。

## 实现约束（落地时按这条走）

- 「…」打开的是**动作面板**，不是设置页：倍速 / 定时退出 / 音效 / 设置四项，沿用现有 `SettingPopup`、`SoundEffectPopup`、`PlaybackRateBtn`、`TimeoutExitBtn` 的能力，不新写一套。
- 规格胶囊的数据只显示**真实已有**的档位（`useStreamInfo().quality`）；采样率/位深透出前不显示 44.1kHz 之类读数。
- 胶囊点击可打开音质选择（与现有 `QualityBtn` 同一个弹层），不是死标签。
- 返回按钮与「…」保持 44pt 命中区；胶囊高度 28pt，但用 hitSlop 补到 44。

## 推翻条件

- 若「…」面板里四项的使用频率被证明高于切歌（需要真实埋点），再考虑把倍速或定时放回顶栏；
- 若后续把播放页改成“标题在封面下方”的 A 排版（内容区已有歌词预览），顶栏可退化为「返回 + 状态文字 + 更多」，届时重画。
